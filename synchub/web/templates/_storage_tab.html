How a worker gets these shares
  1. Add each share here. SMB is the one to start with: Unraid already shares over it. NFS is the alternative; some people see “stale file handle” errors on Unraid’s NFS shares when the mover relocates files, which is why SMB comes first.
  2. On the Workers page choose More → Setup files for a worker. SyncHub writes its docker-compose.yml (Docker mounts the shares itself, so a share that cannot be mounted stops the worker instead of filling a local folder), an .env file, and /etc/fstab lines if you would rather not use Docker.
  3. The Unraid user name and password for SMB shares are entered once in the Share login box below. SyncHub keeps them encrypted and gives them only to a worker that proves its token when setup-worker.sh runs, so a new worker asks nothing.
  4. Create the marker once on each share: docker compose run --rm worker --init-roots. It writes a small {{ marker }} file holding the share’s name. A worker refuses to use a folder without its marker, so an unmounted (empty) folder or the wrong share is never written to.
SyncHub cannot mount anything on a worker PC itself. The “Workers say” column shows what each worker reports about each share: mounted, the right one, writable, and how much space is free.
